# Browser panel (`links.panel`): the default for outside links on Android

James, 9 Nov 2026, after trying the trial on his phone: "Can we go ahead and make this part of core? ... This is way better functionality than any of the previous ones." **On by default for every WizardOS install**; an owner opts out with `links.panel: false`.

**What it does.** A tapped outside http(s) link in a chat, a Search result or a hosted app, inside the WizardOS Android app (0.10.36 or later), opens in a browser panel over Wizard: an Android Custom Tab drawn by the phone's **default browser** when it offers Custom Tabs (the owner's own browser, logins and speed), else by any installed Custom Tabs browser (Brave first among them), else the existing default-browser open. (0.10.36 preferred Brave whenever installed, even over another default; 0.10.37 follows the default browser.) The panel's X or Back returns straight to the chat the link was tapped from. Dark toolbar (`#05030C`), page title shown, the browser's default share button.

**Unchanged.** Desktop, PWA and Mac (a normal new tab), Wizard's own pages (their in-Wizard routes), other Wizards and private/LAN hosts (the existing browser escape), files (downloads), the explicit "Open in your browser" choices (`data-wizard-browse`, long-press, Reader's own button) and Browser Reader (off by default; `links.reader: true` still wins for the links it routes). An older APK without the `openInPanel` bridge keeps `openInBrowser`.

**Where.** Shell: `outside()`/`panelLinks()` in `web/core/links.js` (on unless `links.panel === false`). Native: `Bridge.openInPanel` → `MainActivity.openPanel` and the pure choice `PanelLinks.pick` (`android/app/src/main/java/ai/wizards/os/`), manifest `<queries>` for `android.support.customtabs.action.CustomTabsService`. The setting reaches the shell through the Agent Service's `normalizeSettings` `links` block (wizard-agent-service `server/wizard-os-settings.mjs`, `panel: links.panel !== false`).

**Tests.** `tests/browser-panel-links.test.mjs` (shell: setting absent → panel, `false` → browser, desktop unchanged), `PanelLinksTest` (JVM: default browser first, then Brave, then any provider), `PanelE2eTest` + `tools/qa_android_panel.py` (forum x86_64 emulator with the current Brave release APK made the default browser and its first-run screens skipped: a Custom Tab over WizardOS, one Back returns).

**Turn it off** (no code change): set `"links": {"panel": false}` in `~/.wizard-os/settings.json`. The Agent Service reads the file on every request; the next shell load (reopen the app or pull to reload) opens links in the browser as before. Removing the key turns the panel back on.
