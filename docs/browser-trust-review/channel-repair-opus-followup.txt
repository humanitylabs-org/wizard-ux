## Hardening I'd make (non-blocking, each is one line)

1. **The run-POST check could pass vacuously.** `r.status<400` is false when `status` is `undefined`, for example an aborted or in-flight request or a differently named field. Then a POST to `/runs` would slip through. `sendChat` is stubbed, so any POST to `/runs` at all means the stub was bypassed. A stronger version:
   ```js
   check(report.serviceTrace.length>0 && !report.serviceTrace.some(r=>r.method==='POST' && /\/runs(?:[/?]|$)/.test(r.url)),'browser proof never attempts an owner run');
   ```
   It also matters whether run traffic actually goes through the service that writes `serviceTrace`, rather than the Hermes fixture. If it doesn't, this check proves nothing.
2. **The nonce test doesn't catch a queued pre-auth request.** `wbs-1` is sent before the challenge is answered, but upstream is only checked before the correct reply. If the boundary queued that request and replayed it after `connected`, the test would still pass. Add `await quiet(); assert.equal(f.upstream.length,0);` at the end. Separately, the test currently requires that a correct reply after a wrong guess still connects. That is fine today, but it would break a future fail-closed hardening, so it's worth a comment.
3. **The screenshot count counts paths, not distinct files.** Use `new Set(...).size===5`. If a skin loop ever runs twice, the current check fails for the wrong reason.
4. **Small fixes:**
   - Check that `WizConfig.transcribe` and `chats.sendChat` really equal the stubs after you assign them, in case either object is frozen.
   - Reset `report.phase` after the opacity loop so later lifecycle events aren't tagged `list-opacity-sepia`.
   - Wait for the sheet to detach after `cancelled` too, so the three paths match.
