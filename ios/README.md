# Wizard for iPhone (Capacitor)

The iPhone app for Wizard UX. An iPhone can't run Wizard OS, so the app is a client of a Wizard running elsewhere,
like the Android app in `../android`: a Capacitor web view on that Wizard's `/wizard-os-home/`. Wizard UX picks its
phone shell from the iPhone user agent; the app adds `WizardOS-iOS/<version>` to it.

| What | How |
|---|---|
| Wizard address | Built in from the `WIZARD_ORIGIN` build setting (default `https://wizard.tailc0f369.ts.net`). With no address, or when the Wizard can't be reached, the bundled `www/index.html` shows the connect screen: **Scan QR code**, or type the address; Try again |
| Connect rules | Same as Android (`../android/CONNECT.md`): an https origin only, fail-closed (`WizardOrigin.swift`). An address is saved only after it serves the Wizard shell, with no redirects and no TLS bypass (`WizardProbe`). A scanned code or link connects at once, with no confirmation; a failed check keeps the current Wizard |
| Pairing links | `wizard://connect?origin=<percent-encoded https origin>` (the Setup QR code). The iPhone Camera app or any link opens the app on the connect screen |
| Change Wizard | `Capacitor.Plugins.WizardShell.changeWizard()` from the Wizard's pages shows the connect screen; the current Wizard stays until a new one passes the check |
| Navigation | Pages of the Wizard's host stay in the app; other sites open in Safari |
| Microphone / camera | The page's `getUserMedia` + `MediaRecorder` and file inputs. Capture is granted only to the Wizard's https pages (`MediaGate`), after iOS's own prompt |
| Native features | Capacitor plugins, callable from the Wizard's pages as `window.Capacitor.Plugins.*`: App, Camera, Haptics, LocalNotifications, Preferences, PushNotifications, Share, SplashScreen, StatusBar |
| Back | Left-edge swipe calls `window.__wosNativeBack()` (same contract as Android) |
| Resume | Foregrounding dispatches `wos-native-resume`, like Android |

The app does **not** register a `wizardNative` message handler: Wizard UX reads that name as Wizard for Mac and
would switch to the desktop shell.

## Layout

```
ios/
  capacitor.config.json   Capacitor config (ios.path = native)
  www/index.html          bundled connect / can't-reach screen
  native/App/             Xcode project (generated by `cap add ios`, then customised)
    App/WizardViewController.swift   address, navigation, back, resume, MediaGate, WizardShell plugin
    App/WizardOrigin.swift           address rules + the Wizard check (Foundation only)
    App/QRScannerViewController.swift  camera QR scanner
  tests/origin/run.sh     address checks (the Android cases); runs on any Mac, no Xcode needed
  fastlane/               sim + TestFlight lanes
```

`native/App/App/public`, `capacitor.config.json` and `config.xml` inside it are generated by `npx cap sync ios`
and git-ignored.

## Build and run (Mac with Xcode)

```sh
cd ios
npm ci
npx cap sync ios
npx cap run ios          # pick a Simulator or a connected iPhone
# or: npx cap open ios   # open in Xcode, choose your team under Signing & Capabilities, press Run
```

Compile check without signing: `fastlane sim`.

## TestFlight

Needs `brew install fastlane`, an Apple Developer team, an App Store Connect app record for `APP_IDENTIFIER`, and an
App Store Connect API key (Admin role, for automatic cloud signing).

```sh
cp fastlane/.env.example fastlane/.env   # fill it in; keep the .p8 outside the repo
fastlane beta                            # build number = latest TestFlight build + 1
```

Internal TestFlight testers (members of the App Store Connect team) can install as soon as processing finishes,
without Apple review. Testers need to reach the Wizard: for a tailnet address, Tailscale must be on.

## Not done yet

- Push notifications: the plugin and the `aps-environment` entitlement are in, but nothing sends pushes yet. Needs an
  APNs key and a device-token endpoint plus sender in the Agent Service. A free (personal) Apple team can't sign the
  push entitlement; remove `CODE_SIGN_ENTITLEMENTS` to test on such a team.
- Receiving shares from other apps (iOS Share Extension), home-screen Quick Actions.
- Wizard UX doesn't use the plugins yet (e.g. `Share` instead of `navigator.share`, haptics); that's a `web/` change.
- Sign-in redirects through other sites would open in Safari; add those hosts to `allowedNavigationHostnames` if a
  Wizard uses one.
